# 仓库卫生规范

版本：v0.1
日期：2026-06-15

## 工作树原则

- 不还原他人的未提交改动。
- 清理旧实现、加规范、改功能分批进行。
- 每批删除后立即运行最小验证。
- 不把日志、临时截图和无关 import 变动混进业务改动。

## 生产与非生产

非生产内容包括：

- `scripts/autotest/` 下验证脚本。
- `design_img/` 参考图。
- `output/` 验证输出。
- `logs/` 运行日志。
- 已被替换但尚未删除的旧场景/旧脚本。

非生产不等于可删。删除前必须确认没有文档、测试或人工流程依赖。

## 日志和输出

`logs/` 与 `output/` 默认视作本地/验证产物。

建议：

- 长期保留的截图放入文档指定位置。
- 一次性验证截图放入 `output/verification/`，提交前按需清理。
- Godot 自动生成的日志不要作为功能提交的一部分。

## `.uid` 和 `.import`

- 生产 `.gd` 对应 `.uid` 在 Godot 4 项目中可以保留。
- 新增运行时 PNG 时，对应 `.import` 可保留。
- 删除脚本/场景/图片时，同批删除对应 `.uid` / `.import`。
- 不为临时输出、日志截图、废弃原型保留新的 `.import`。

## 旧实现清理

清理顺序：

1. 一次只删除同一功能的一组旧文件。
2. 删除后运行最小验证。
3. 如果失败，先定位是删除导致还是已有测试债。
4. 通过后再进入下一组清理。

## `.gitignore` 建议

当前 `.gitignore` 只覆盖 `.godot/` 和 `/android/`。进入量产前建议补充：

```gitignore
logs/
output/
*.tmp
```

是否忽略 `*.import` 不应一刀切；运行时图片对应 `.import` 仍可能需要提交。

## 提交前检查

提交前至少确认：

```bash
git status --short
godot --headless --quit
```

提交说明应写清：

- 改了哪个范围。
- 跑了哪些验证。
- 是否仍有已知风险。

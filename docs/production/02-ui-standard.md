# UI 制作规范

版本：v0.1
日期：2026-06-15

## UI 目标

量产 UI 以 Godot 原生 `Control` 场景为主。HTML 原型和截图只作为设计参照，不作为运行时依赖。

生产 UI 必须满足：

- 场景树能在编辑器中读出主要结构。
- 脚本只负责状态、数据绑定、动态列表和交互。
- 主题、字号、颜色、间距尽量通过统一 token 或 helper 管理。
- 每个页面有清晰的验证命令。

## 场景与脚本分工

`.tscn` 应承载：

- 页面根容器、背景层、主布局。
- 大面板、标题区、按钮区、列表容器。
- 重复项的内部结构。
- 弹窗、Toast、固定徽章、TextureRect 占位。

脚本应负责：

- 读取上下文和数据。
- 设置文本、图像和状态。
- 实例化动态列表项。
- 连接信号和处理输入。
- 少量无法静态表达的布局修正。

不推荐把完整页面用脚本动态创建。临时转换阶段允许，但进入量产前应回收成稳定场景结构。
严禁在 `_ready()` 里重复设置本可直接写进场景的静态属性。只有依赖运行时数据、动态状态或实例化结果时，才允许在脚本里设置对应值。

## 全屏覆盖层

全屏覆盖界面必须提供固定在右上角的关闭按钮

- 关闭按钮不放在滚动区域、列表末尾或主内容底部。
- 按钮尺寸不小于 44x44，样式使用当前 UI helper 或主题 token。
- 关闭动作发出对应的 completed/back 信号，由上层流程决定返回或关闭页面。
- 新增覆盖层时优先在 `.tscn` 中放置 Header/关闭按钮，只有临时转换阶段才用脚本创建。

## 子场景拆分

优先拆成子场景：

- 页面级模块。
- 大面板。
- 重复列表项。
- 复合控件。
- 弹窗、Toast。
- 多页面复用的按钮组。

不拆：

- 单个静态 Label。
- 纯布局容器。
- 一次性装饰线。
- 只服务当前父节点的内部小元素。

## 主题和视觉 token

当前 HD-2D 风格应沉淀为：

- `assets/ui/themes/*.tres`：Godot Theme 或共享主题资源。
- 本文档中的 token 表。

基础 token：

| 名称 | 用途 |
| --- | --- |
| `COLOR_BACKDROP` | 全屏底色/暗化层 |
| `COLOR_BG` | 页面主背景 |
| `COLOR_PANEL` | 主面板 |
| `COLOR_ROW` | 列表项/按钮底 |
| `COLOR_GOLD` | 重点边框、标题、主按钮 |
| `COLOR_TEXT` | 正文 |
| `COLOR_MUTED` | 次级说明 |

新增 UI 不直接散落新色值。确需新增颜色时，先补 token 和用途。

## 布局规则

- 页面设计基准为 1920x1080，HUD 内部可使用 1600x900 设计根，但必须有响应式约束。
- 固定尺寸控件必须设置 `custom_minimum_size` 或明确容器规则，避免文本/状态改变导致抖动。
- 页面级背景使用全屏锚点，主要内容使用容器布局或明确设计根缩放。
- 不在面板里套面板。页面区块不要全部做成浮动卡片。
- 文本必须在 1280x720 和 1920x1080 下不遮挡、不溢出关键按钮。

## 交互状态

常见状态必须设计并实现：

- `normal`
- `hover`
- `pressed`
- `focused`
- `disabled`
- `selected`

手柄/键盘路径进入量产后必须纳入设置、地图等核心页面的验收。

仅用于绘制连线、调试图形或覆盖装饰的全屏 `Control` 必须设置：

```gdscript
mouse_filter = Control.MOUSE_FILTER_IGNORE
```

否则后添加的同级覆盖层会拦截下方按钮的输入。

## UI 验收

UI 改动至少运行：

```bash
godot --headless --quit
```

地图/设置等改动运行对应验证脚本，并在需要时截图检查。

# PRD 生成器

创建清晰、可操作且适合实施的详细产品需求文档。

---

## 工作内容

1. 从用户接收功能描述
2. 提出 3-5 个关键澄清问题（带字母选项）
3. 培于回答生成结构化的 PRD
4. 保存到 `tasks/prd-[feature-name].md`

**重要：** 不要开始实现。只创建 PRD。

---

## 步骤 1：澄清问题

仅在初始提示模糊时提出关键问题。聚焦于：

- **问题/目标：** 这解决什么问题？
- **核心功能：** 关键操作是什么？
- **范围/边界：** 它不应该做什么？
- **成功标准：** 我们如何知道它完成了？

### 问题格式示例：

```
1. 这个功能的主要目标是什么？
   A. 改善用户引导体验
   B. 提高用户留存率
   C. 减少支持负担
   D. 其他：[请说明]

2. 目标用户是谁？
   A. 仅新用户
   B. 仅现有用户
   C. 所有用户
   D. 仅管理员用户

3. 范围是什么？
   A. 最小可行版本
   B. 全功能实现
   C. 仅后端/API
   D. 仅 UI
```

这样用户可以用"1A, 2C, 3B"快速回复。记得缩进选项。

---

## 步骤 2：PRD 结构

生成包含以下章节的 PRD：

### 1. 简介/概述
功能及其解决问题的简要描述。

### 2. 目标
具体、可衡量的目标（要点列表）。

### 3. 用户故事
每个故事需要：
- **标题：** 简短描述性名称
- **描述：** "作为[用户]，我想要[功能]以便[收益]"
- **验收标准：** 可验证的"完成"定义检查清单

每个故事应小到可以在一个专注的会话中实现。

**格式：**
```markdown
### US-001: [标题]
**描述：** 作为[用户]，我想要[功能]以便[收益]。

**验收标准：**
- [ ] 具体可验证的标准
- [ ] 另一个标准
- [ ] Typecheck/lint 通过
- [ ] **[仅 UI 故事]** 使用 dev-browser 技能在浏览器中验证
```

**重要：**
- 验收标准必须可验证，不能模糊。"正常工作"不好。"按钮在删除前显示确认对话框"好。
- **对于任何有 UI 变更的故事：** 始终包含"使用 dev-browser 技能在浏览器中验证"作为验收标准。这确保前端工作的视觉验证。

### 4. 功能需求
编号的具体功能列表：
- "FR-1: 系统必须允许用户..."
- "FR-2: 当用户点击 X 时，系统必须..."

明确且无歧义。

### 5. 非目标（范围外）
此功能不包含什么。对管理范围至关重要。

### 6. 设计考量（可选）
- UI/UX 需求
- 链接到模型（如果有）
- 要复用的相关现有组件

### 7. 技术考量（可选）
- 已知约束或依赖
- 与现有系统的集成点
- 性能需求

### 8. 成功指标
如何衡量成功？
- "将完成 X 的时间减少 50%"
- "将转化率提高 10%"

### 9. 开放问题
剩余问题或需要澄清的领域。

---

## 为初级开发者编写

PRD 读者可能是初级开发者或 AI agent。因此：

- 明确且无歧义
- 避免术语或解释它
- 提供足够细节以理解目的和核心逻辑
- 编号需求以便引用
- 在有帮助时使用具体示例

---

## 输出

- **格式：** Markdown（`.md`）
- **位置：** `tasks/`
- **文件名：** `prd-[feature-name].md`（kebab-case）

---

## 示例 PRD

```markdown
# PRD: 任务优先级系统

## 简介

为任务添加优先级级别，让用户可以专注于最重要的事情。任务可以标记为高、中或低优先级，配合视觉指示器和过滤功能帮助用户有效管理工作负载。

## 目标

- 允许为任何任务分配优先级（高/中/低）
- 提供优先级级别之间的清晰视觉区分
- 支持按优先级过滤和排序
- 新任务默认为中优先级

## 用户故事

### US-001: 为数据库添加优先级字段
**描述：** 作为开发者，我需要存储任务优先级以便跨会话持久化。

**验收标准：**
- [ ] 为 tasks 表添加 priority 列：'high' | 'medium' | 'low'（默认 'medium'）
- [ ] 成功生成并运行迁移
- [ ] Typecheck 通过

### US-002: 在任务卡片上显示优先级指示器
**描述：** 作为用户，我想要一目了然地看到任务优先级以便知道什么需要优先处理。

**验收标准：**
- [ ] 每个任务卡片显示彩色优先级徽章（红=高，黄=中，灰=低）
- [ ] 无需悬停或点击即可看到优先级
- [ ] Typecheck 通过
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-003: 为任务编辑添加优先级选择器
**描述：** 作为用户，我想要在编辑任务时更改其优先级。

**验收标准：**
- [ ] 任务编辑模态框中有优先级下拉菜单
- [ ] 显示当前优先级为选中状态
- [ ] 选择变更时立即保存
- [ ] Typecheck 通过
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-004: 按优先级过滤任务
**描述：** 作为用户，我想要过滤任务列表以便专注时只看高优先级项目。

**验收标准：**
- [ ] 过滤下拉菜单选项：全部 | 高 | 中 | 低
- [ ] 过滤器在 URL 参数中持久化
- [ ] 没有匹配过滤器的任务时显示空状态消息
- [ ] Typecheck 通过
- [ ] 使用 dev-browser 技能在浏览器中验证

## 功能需求

- FR-1: 为 tasks 表添加 `priority` 字段（'high' | 'medium' | 'low'，默认 'medium'）
- FR-2: 在每个任务卡片上显示彩色优先级徽章
- FR-3: 在任务编辑模态框中包含优先级选择器
- FR-4: 为任务列表头部添加优先级过滤下拉菜单
- FR-5: 在每个状态列内按优先级排序（高到中到低）

## 非目标

- 不添加基于优先级的通知或提醒
- 不根据截止日期自动分配优先级
- 不为子任务添加优先级继承

## 技术考量

- 复用现有徽章组件并添加颜色变体
- 通过 URL 搜索参数管理过滤状态
- 优先级存储在数据库中，不计算

## 成功指标

- 用户可以在 2 次点击内更改优先级
- 高优先级任务在列表顶部立即可见
- 任务列表性能无回归

## 开放问题

- 优先级是否应影响列内任务排序？
- 是否应为优先级更改添加键盘快捷键？
```

## 检查清单

保存 PRD 前：

- [ ] 提出了带字母选项的澄清问题
- [ ] 纳入了用户的回答
- [ ] 用户故事小而具体
- [ ] 功能需求编号且无歧义
- [ ] 非目标章节定义了清晰边界
- [ ] 保存到 `tasks/prd-[feature-name].md`

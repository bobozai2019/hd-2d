# HTML 转 Godot UI

## 核心规则

将 HTML 原型同时视为三个来源：DOM 结构、CSS 视觉/布局规则和 JS 数据/行为。不要在 Godot 中嵌入 HTML。将其翻译为原生 `Control` 场景，其中 `.tscn` 文件拥有稳定的可见结构和可序列化控件属性，而脚本拥有数据绑定、状态、事件、动态重复项和业务行为。

总原则：能不写脚本就不写脚本。凡是可以由场景/资源序列化表达的 UI 内容与表现，默认都放在 `.tscn`、`Theme` 或 `.tres` 中实现，不在 `_ready()` 或初始化辅助函数里赋值。脚本仅用于场景/资源无法承担、且确实需要运行时变化的部分（如数据驱动状态、交互驱动状态切换、业务逻辑与动态刷新）。

转换和重构时的场景优先强制规则：

1. 所有固定 UI 默认值优先编辑 `.tscn`。
2. 脚本仅限于动态状态更新、数据绑定、运行时行为和交互处理。
3. 将值从脚本迁移到场景时，按此顺序提交：写入场景默认值 -> 验证场景加载/视觉基线 -> 删除脚本赋值。
4. 在 `.tscn`/资源中存在并验证相同默认值之前，不要删除脚本侧的静态初始化。

按以下优先级优化：

1. 保留页面尺寸、主面板尺寸、关键卡片尺寸、图标槽位尺寸、间距和 padding。
2. 保留容器分区、兄弟顺序、grid 轨道和换行结果。
3. 保留交互状态和 JS 数据行为。
4. 精修视觉材质、光照、阴影和截图保真度。

永远不要仅仅为了让 UI "看起来更像 Godot" 就改变尺寸、grid 结果或容器顺序。

## 必须的参考文件

仅在需要时加载参考文件：

- 在实现或审查页面转换之前，阅读 `references/conversion-manual.md`。它包含完整的转换工作流、资产规则、目录约定、L0-L4 验收门和检查清单。
- 在声称交互工作完成之前，阅读 `references/interaction-acceptance.md`。headless 加载不能证明点击、拖动、焦点或状态写入正常工作。

## 工作流程

对于每个 HTML 页面：

1. 检查 HTML 并按顺序列出主要 DOM 区域。
2. 检查 CSS 并记录固定尺寸、最小尺寸、宽高比、间距、padding、flex/grid 规则、伪元素、SVG 和类图像装饰。
3. 检查 JS 并列出数据表、选中/当前状态、禁用/售出状态、筛选器、事件和写回行为。
4. 在编码前创建尺寸/布局映射：页面设计尺寸、主面板、卡片、图标槽位、grid 列/行和 DOM 到 Godot 节点映射。
5. 决定场景拆分：页面根、大面板、重复项场景、复合控件、浮层和可复用通用控件。
6. 先将可见固定结构和固定控件属性构建到 `.tscn` 中。保持页面根、背景、面板、固定按钮、标题、列表容器、详情面板、Toast 壳、资产占位、默认可见性、固定文本、尺寸、主题覆盖和纹理为静态。
7. 脚本仅用于数据绑定、重复项实例化、状态切换、信号、动画、弹窗和运行时更新。在编写任何 `_ready()` UI 赋值之前，检查相同值是否应属于场景或资源。
8. 清理现有场景时，检查每个 `_ready()` 调用链（包括 `_ready()` 调用的辅助方法），先将固定赋值移到场景/资源中；然后删除冗余的脚本赋值。
9. 将需要的 SVG/CSS 类图像资产转换为 PNG/NinePatch/StyleBoxTexture，并通过 `TextureRect`、`NinePatchRect` 或样式资源接入。
10. 对主场景和关键子场景运行 Godot headless，捕获加载、脚本和节点路径错误。
11. 将鼠标、拖动、焦点、选中、按下、禁用、售出和业务操作行为与 headless 加载分开验证。
12. 以验收清单结束，对于高保真阶段，进行 HTML/Godot 截图对比。

推荐加载检查：

```powershell
godot --headless --path . --scene res://scenes/<module>/<PageRoot>.tscn --quit-after 1
godot --headless --path . --scene res://scenes/<module>/<KeySubScene>.tscn --quit-after 1
```

## 红线

- 不要让页面根只是一个空壳，主要在 `_ready()` 中组装。
- 当 Godot 可以在 `.tscn`、`Theme` 或 `.tres` 中序列化时，不要将固定 UI 属性移到脚本中。
- 不要将 `_ready()` 用作文本、尺寸、颜色、主题覆盖、纹理、默认可见性、焦点模式或容器常量的批量样式/布局初始化器。
- 除非最终的行/列放置和顺序保持等价，否则不要用 `VBoxContainer` 或 `HBoxContainer` 替换 HTML grid。
- 不要让 Godot 容器默认值静默拉伸或缩小固定尺寸的 HTML 面板、卡片、按钮或图标槽位。
- 不要用 Label 文本作为所需图标、物品美术、角色美术、页面标记或其他类图像 SVG/CSS 内容的长期替代。
- 如果心形标记、菱形标记、星形标记、计数器或标记条在 HTML 中承载图标、资源或状态含义，不要将它们视为普通文本。
- 当需要独立控件、文本更新、本地化或交互时，不要将整个 UI 截图变成背景图。
- 不要在页面 `_ready()` 中注册全局 `InputMap` 操作。使用项目级操作或现有的项目初始化器。
- 不要因为 headless 加载通过或截图看起来正确就标记交互完成。

## Godot 映射偏好

- 将 `display: flex` 映射为 `HBoxContainer` 或 `VBoxContainer`。
- 将常规 `display: grid` 映射为 `GridContainer`，需要时设置子元素最小尺寸。
- 对于复杂的 CSS grid 跨列跨行，仅在最终顺序、分组和视觉单元格放置与 HTML 匹配时才使用嵌套容器或手动定位。
- 将 `gap` 映射为容器间距常量，将 `padding` 映射为 `MarginContainer` 或面板内容边距。
- 保持文本、价格、描述、标签、按钮、开关、滑条和值为 Godot 原生控件。将静态默认值直接放在 `.tscn` 中的控件上；脚本只刷新数据驱动值。
- 优先使用 `@onready` 绑定到稳定的 `.tscn` 节点，并暴露小方法如 `setup(data)`、`set_selected(value)` 和 `refresh()`。

## 验收门

使用分阶段验收：

- `L0`：场景在 Godot 中加载。
- `L1`：主要结构、尺寸、DOM 顺序、grid 结果和数据存在。
- `L2`：hover、focus、selected、disabled、sold 和值状态正确刷新。
- `L3`：必须的 PNG/NinePatch 资产已连接；没有必须的图标/美术仍是文本占位。
- `L4`：截图在布局、资产存在、状态表达和文本密度上足够接近。

尺寸验收必须在两个层级通过：

- 页面级：侧边栏、顶部栏、底部操作区、卡片带和主面板等主要分区在尺寸和放置上与 HTML 匹配。
- 组件级：进度条、徽记、图标条、计数器、符号行和标题/正文间距等高风险小元素在长度、厚度、相对位置和视觉权重上也与 HTML 匹配。

在最终验收前，验证：

- 主要尺寸、间距、padding、面板顺序和 grid 结果与 HTML 原型匹配。
- 页面级尺寸相似性没有被用作组件级尺寸检查的替代。
- 固定可见结构和固定可序列化 UI 属性在 `.tscn` 或资源中，而非由脚本生成或批量赋值。
- JS 数据和状态已迁移到可维护的 Godot 数据/状态脚本中。
- 必须的 SVG/CSS 伪元素资产已清点并处理。
- 动态列表清理旧节点、避免重复信号、有意恢复选择/焦点，并处理空列表。
- 鼠标点击、hover/focus、按下反馈、拖动控件、底部/侧边操作和状态写回确实正常工作。

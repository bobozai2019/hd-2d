# 交互控件

当控件选择由 click/focus/hover 行为驱动时使用本文件。

## `Button`

- 是什么：标准可点击控件。
- 自动行为：pressed、hover、focus、disabled 状态。
- 适合场景：HTML 元素是真正的操作目标。
- 最常见误用：过早地用纯 `Control` + 手动信号重建按钮语义。
- HTML 映射问题：这个节点是操作目标，还是只是操作目标的视觉包裹层？

## `CheckBox` / 开关类控件

- 是什么：用于二元状态的内置交互控件。
- 自动行为：focus、pressed、toggled 和 disabled 状态由控件管理。
- 适合场景：HTML 元素本质上是开/关状态控件，即使外壳是自定义样式。
- 最常见误用：用可点击包裹层和独立装饰状态节点构建假开关，然后丢失语义状态管理。
- HTML 映射问题：这个区块是在选择开/关，还是只是显示一个视觉标签？

## 标签页式或分段选择

- 是什么：一组互斥的操作目标，同时影响可见状态。
- 自动行为：选择管理应是显式的，即使最终外壳是自定义的。
- 适合场景：HTML 区块表现为标签页、分段控件或类别标签，其中一个活动状态改变其余 UI。
- 最常见误用：将每个分段视为没有共享选择模型的独立装饰按钮。
- HTML 映射问题：这真的是一行独立按钮，还是一个共享活动状态的选择组？

## 选择器式控件

- 是什么：从有限集合中选择一个选项的控件或控件组。
- 自动行为：focus、活动选项和值管理应存在于显式选择器结构中。
- 适合场景：HTML 区块是下拉式、拾取器式或选项切换区域。
- 最常见误用：让可见壳、选中文本和点击目标分属不相关节点。
- HTML 映射问题：哪个节点拥有当前值，哪个节点只是渲染它？

## 交互壳规则

当 HTML 元素既是视觉壳又是操作目标时：

- 保持操作目标显式。
- 防止装饰子元素吞掉输入。
- 如果真正的按钮可以管理操作，避免让整个区块手动可点击。

## 焦点与悬停

如果 focus/hover 影响结构决策：

- 考虑内部内容是否应由按钮内的布局容器排列。
- 考虑装饰层是否应忽略输入。
- 考虑交互节点应拥有内容壳还是包裹它。

## 必须的交互产出

使用本文件时，最终决策还应回答：

- 真正的操作目标是什么？
- 哪个节点拥有选择或值状态？
- 哪些装饰子元素必须忽略输入？
- 这是一个控件，还是一个共享活动状态的分组控件？

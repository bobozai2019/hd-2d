# 常见失败模式

保持诊断简洁。将当前症状与以下模式匹配。

## `PanelContainer` 被当作纯背景壳

- 症状：子元素拉伸、重叠，或行为不像中性板。
- 根因：在只需要视觉壳的地方使用了管理布局的容器。
- 误判："看起来像面板，所以一定是正确节点。"
- 修复方向：将壳与内容体分离，或对壳使用 `Panel`/`Control`。

## `Container` 家族与手摆 offset 混用

- 症状：子元素似乎与预期放置位置冲突。
- 根因：容器布局语义和手动定位在往不同方向拉。
- 误判："节点还能移动，所以语义一定没问题。"
- 修复方向：判断区块是布局驱动还是自由定位，然后相应重建。

## 页面级尺寸接近，组件级尺寸错误

- 症状：页面大致匹配，但进度条、徽记、计数器或标题/正文比例感觉不对。
- 根因：小内容节点被赋予了错误的结构角色。
- 误判："元素存在了，所以映射一定是完整的。"
- 修复方向：重新检查高风险组件的节点角色，检查其父子结构。

## 辅助元素变成主导视觉块

- 症状：短进度条、填充条或徽记变成了 UI 的一大块。
- 根因：内容/填充节点承担了壳或布局职责。
- 误判："只需要调整尺寸。"
- 修复方向：将壳/布局职责向外移；保持辅助元素小而从属。

# Container 家族

当 HTML 区块需要自动排列子元素时使用本文件。

对于以下每个控件，先回答 HTML 到 Godot 的映射问题，再选择节点。

## `Container`

- 是什么：自动排列子控件的基类。
- 自动行为：子布局由容器管理，而非自由定位。
- 适合场景：HTML 区块本质上是排列子元素。
- 最常见误用：把它当作纯装饰性空壳。
- HTML 映射问题：这个区块是否主要是按顺序、行、列、轨道或边距放置子元素？

## `PanelContainer`

- 是什么：带面板样式的样式化内容容器。
- 自动行为：仍然像容器一样参与子布局。
- 适合场景：HTML 区块是一个有框内容区域，内部只有一个内容区域。
- 最常见误用：把它当纯背景板，下面直接塞多个手摆子节点。
- HTML 映射问题：这是一个有单个内容体的内容面板，还是只是一个视觉框？
- 不确定时更安全的模式：`PanelContainer -> Shell -> Body`

## `HBoxContainer`

- 是什么：水平子元素排列器。
- 自动行为：从左到右放置子元素并带间距。
- 适合场景：HTML 使用 flex-row 样式排序。
- 最常见误用：用于实际需要手动重叠、绝对对齐或 grid 行为的结构。
- HTML 映射问题：兄弟节点顺序是否是主要结构？

## `VBoxContainer`

- 是什么：垂直子元素排列器。
- 自动行为：从上到下放置子元素并带间距。
- 适合场景：HTML 使用列流。
- 最常见误用：用垂直堆叠替代真正的 grid 或自由定位壳。
- HTML 映射问题：这个区块真的是垂直列表还是堆叠壳？

## `GridContainer`

- 是什么：规则网格布局容器。
- 自动行为：将子元素放入一致的列网格中。
- 适合场景：HTML grid 规则到 Godot 列数能保留相同的视觉结果。
- 最常见误用：将复杂的跨列跨行强制塞入简单 grid，丢失放置语义。
- HTML 映射问题：HTML grid 是否表现为可重复的等宽轨道，还是需要特殊的跨列跨行？

## `MarginContainer`

- 是什么：提供内容内边距的包裹层。
- 自动行为：通过显式边距将子内容向内推。
- 适合场景：HTML 行为主要是对子区域的 padding。
- 最常见误用：把它当作还需要行列排列的区块的主布局引擎。
- HTML 映射问题：这里的关键行为是 padding，而不是排列？

## `ScrollContainer`

- 是什么：可滚动内容的视口式包裹层。
- 自动行为：裁剪和滚动子内容。
- 适合场景：HTML 区块有 overflow/scroll 语义。
- 最常见误用：在不需要滚动时仅把它当作裁剪壳使用。
- HTML 映射问题：overflow 行为是 HTML 含义的一部分，还是只是副作用？
